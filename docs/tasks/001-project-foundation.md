# Task 001 — Project Foundation

## Objective
Create the Xcode project, the SwiftUI app target, the DeviceActivityMonitor extension target, the folder structure from Appendix A, and App Group preparation.

**Acceptance:** the project builds and the extension target exists.

## In scope
- Xcode project `ScreenTimeNext.xcodeproj` with a SwiftUI app target named `ScreenTimeNext`.
- A DeviceActivity monitor extension target named `DeviceActivityMonitorExtension`.
- A unit test target.
- Xcode groups mirroring the on-disk layout in Appendix A (`Core/`, `Features/`, `ScreenTime/`, `Shared/`, `DeviceActivityMonitorExtension/`).
- A single App Group identifier constant in `Packages/ScreenTimeNextCore/Sources/ScreenTimeNextCore/Constants/` shared by both targets.
- Capabilities added to both targets: App Groups; Family Controls where the account permits.

## Out of scope
- Any service protocol or implementation (→ Task 002).
- Any call into FamilyControls / DeviceActivity / ManagedSettings (→ Tasks 004, 005, 010, 011).
- Any UI beyond the default app shell (→ Task 003).

## PRD detail
Appendix A defines the folder layout. The layout encodes one rule: `import FamilyControls`, `import DeviceActivity`, and `import ManagedSettings` may appear **only** under `ScreenTimeNext/ScreenTime/` and `DeviceActivityMonitorExtension/`.

The repository already contains this directory skeleton with `.gitkeep` files — the task is to make Xcode reference it, not to invent a new layout.

## Implementation notes
- **Phase 0 / free account (D-007):** Family Controls and App Groups capabilities cannot be added on a Personal Team. Create the extension target and the App Group constant anyway, leave both capabilities unchecked, and record them as blocked-by-gate in the completion report — not as failures. Use a Personal Team for signing; expect the 7-day reinstall cycle.
- The `.xcodeproj` must be generated by Xcode. Do not hand-author project file XML.
- The App Group identifier requires a real Apple Developer Team ID. If none is configured, define the constant with a clearly-marked placeholder, mark the task **BLOCKED** on that step, and record it in `docs/BLOCKERS.md`.
- The Family Controls capability is entitlement-gated (PRD §18). Adding the capability may fail on a personal team — that is expected and must be logged as a blocker, not worked around.
- Confirm the deployment target against the installed SDK before setting it.

## Architecture rules in force
- Rule 5 — App Groups are the sharing mechanism between app and extension. Set this up now, not later.
- Rule 8 — use the current installed Xcode/iOS SDK.
